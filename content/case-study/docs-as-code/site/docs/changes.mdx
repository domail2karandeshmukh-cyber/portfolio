# Changes

## 1.2 (2026-11-28) {#1-2}

- **Fixed:** the order of the reset, in the admin console and in the REST API.
  The guide deleted the OTP credential first and added **Configure OTP** second, which let the user sign in with the password alone between the two actions.
  A test on Keycloak 26.8.2 confirmed it. The guide now adds the required action first: Keycloak then asks for a code until the deletion, and for a new authenticator after it.
- **Added:** what the user needs before you start, and what to do if the password may also be known to someone else.
- **Changed:** every screenshot caption now names its step and says what to look at, and step 5 tells you what to check instead of quoting Keycloak's success message.

## 1.1 (2026-11-27) {#1-1}

- **Added:** [Reset many users with the admin REST API](./how-to/reset-otp.mdx#rest-api).
  After a change to the OTP policy, every user needs a reset, and the console does one at a time.
  Every command ran as written against Keycloak 26.8.2.
- **Added:** a warning that a `PUT` of a user's required actions replaces the whole list.
  Found while testing the commands: sending `CONFIGURE_TOTP` alone removed a pending profile update.
- **Fixed:** the review date on every page.

## 1.0 (2026-11-27) {#1-0}

- First version, migrated from the help-center article *How to reset 2FA*: a concept, a how-to, a reference, a troubleshooting page, and a terminology list.
