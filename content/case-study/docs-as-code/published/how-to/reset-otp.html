Reset a user's one-time password

Type
How-to
For
Keycloak administrators
Checked against
Keycloak 26.8.2
Owner
Karan Deshmukh
Last review
2026-11-27

When a user loses or replaces the phone that holds their authenticator, delete its one-time password (OTP) credential. Then make the user set up a new one at their next sign-in.

Before you start​

Confirm who is asking

Reset an authenticator only for the account's owner. Confirm the request through contact details the user gave before they lost the phone, not through details in the request. A reset for anyone else gives them the account.

  • Sign in to the admin console with an account that can manage the users of the user's realm.
  • Have the user's username or email address.

Steps​

  1. In the admin console, check that the user's realm is the current realm: its name is at the top of the menu. Select Users, search for the user, and select their username.

  2. Select the Credentials tab. Find the row of type Otp. Its user label names the device, such as Alex's phone.

  3. Open the row's menu, and then select Delete.

  4. In Delete credentials?, select Delete. Keycloak reports The credentials has been deleted successfully., and only the password is left on the tab.

    Don't stop here

    The user can now sign in with the password alone. Keycloak asks for a code only from a user who has a second factor set up. Step 5 makes the user set up a new one.

  5. Select the Details tab. In Required user actions, select Configure OTP, and then select Save. Keycloak reports The user has been saved.

  6. Ask the user to sign in. After their password, Keycloak shows Mobile Authenticator Setup. They scan the code with an authenticator app on the new phone, type the code the app shows, name the device, and select Submit.

Check that it worked​

On the Credentials tab, a new Otp row shows the name the user gave the new device, with today's date.

When the realm saves admin events, Events > Admin events lists the deletion as an ACTION on the user's credential, and the new required action as an UPDATE of the user.

Reset many users with the admin REST API​

After a change to the OTP policy, every user's authenticator needs a reset, and the admin console does one user at a time. The admin REST API does the same two things: it deletes the OTP credential, and it adds Configure OTP to the user's required actions.

Confirm who is asking

Reset an authenticator only for the account's owner. Confirm the request through contact details the user gave before they lost the phone, not through details in the request. A reset for anyone else gives them the account.

Set these variables first. Read the password from a password manager or a prompt, so that it stays out of your shell history.

Variables
KC_URL=https://keycloak.example.com   # your Keycloak server
REALM=portfolio-demo                  # the user's realm
KC_ADMIN=sam.rivera                   # an administrator of the master realm
USERNAME=alex.morgan                  # the user to reset
read -rs -p "Password for $KC_ADMIN: " KC_ADMIN_PASSWORD; echo

  1. Get an access token for the admin REST API, and find the user's ID.

    TOKEN=$(curl -s "$KC_URL/realms/master/protocol/openid-connect/token" \
      -d grant_type=password -d client_id=admin-cli \
      --data-urlencode "username=$KC_ADMIN" --data-urlencode "password=$KC_ADMIN_PASSWORD" | jq -r .access_token)
    USER_ID=$(curl -s -H "Authorization: Bearer $TOKEN" \
      "$KC_URL/admin/realms/$REALM/users?username=$USERNAME&exact=true" | jq -r '.[0].id')

  2. Delete each of the user's OTP credentials. Keycloak answers each deletion with 204 No Content.

    for ID in $(curl -s -H "Authorization: Bearer $TOKEN" "$KC_URL/admin/realms/$REALM/users/$USER_ID/credentials" \
      | jq -r '.[] | select(.type == "otp") | .id'); do
      curl -s -o /dev/null -w '%{http_code}\n' -X DELETE -H "Authorization: Bearer $TOKEN" \
        "$KC_URL/admin/realms/$REALM/users/$USER_ID/credentials/$ID"
    done

  3. Add CONFIGURE_TOTP to the user's required actions.

    Keep the actions already there

    A PUT replaces the user's whole list of required actions. Sending {"requiredActions": ["CONFIGURE_TOTP"]} alone removes any action the user still has to do, such as updating their profile. Read the list first and add to it, as this command does.

    ACTIONS=$(curl -s -H "Authorization: Bearer $TOKEN" "$KC_URL/admin/realms/$REALM/users/$USER_ID" \
      | jq -c '.requiredActions + ["CONFIGURE_TOTP"] | unique')
    curl -s -o /dev/null -w '%{http_code}\n' -X PUT -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
      -d "{\"requiredActions\": $ACTIONS}" "$KC_URL/admin/realms/$REALM/users/$USER_ID"

  4. Check the result. The credentials list holds the password only, and the required actions include CONFIGURE_TOTP.

    curl -s -H "Authorization: Bearer $TOKEN" "$KC_URL/admin/realms/$REALM/users/$USER_ID/credentials" | jq -c '[.[] | .type]'
    curl -s -H "Authorization: Bearer $TOKEN" "$KC_URL/admin/realms/$REALM/users/$USER_ID" | jq -c '.requiredActions'
    Output
    ["password"]
    ["CONFIGURE_TOTP","UPDATE_PROFILE"]

At their next sign-in, Keycloak runs the user's required actions one after another, and asks them to set up an authenticator before they get in.
